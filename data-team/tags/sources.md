What it adds: the period and balance type of all 5 match how we store them (duration; credit for all except CostsAndExpenses, which is debit). None of the 5 is deprecated in 2026 (564 us-gaap rows are in the 2026 Deprecated_Items sheet; none is a key tag). The calculation trees confirm three card claims from the taxonomy side: CostsAndExpenses has no interest child; InterestRevenueExpenseNet is the PARENT of InterestIncomeExpenseNet, not a synonym; Revenues is the parent of RevenuesNetOfInterestExpense, so net and gross bank revenue are different concepts.

### Pull 2: FSDS 2025q4 (`tag.txt`, `pre.txt`, `sub.txt`)
- Definition drift: the us-gaap/2024 and us-gaap/2025 definitions of all 5 tags are word-for-word the same as 2026, so the three taxonomy versions our recent facts use do not differ for these tags.
- Face-statement reach (distinct CIKs with the tag on IS/BS/CF/CI/EQ in a 10-K/10-Q filed in the quarter, by SIC family): InterestIncomeExpenseNet 720 (bank 381, other 246, REIT 49, pharma 35); InvestmentIncomeInterest 1,201 (other 844, pharma 234, REIT 55, bank 27); CostsAndExpenses 1,104 (other 634, REIT 168, pharma 121, energy 72, utility 71, bank 28); OperatingIncomeLoss 4,342 (bank-range 97, insurer 16); Revenues 1,849 (insurer 111, bank-range 83).

- Method: the scripts are in the scratchpad (`fsds_pre.py`, `fsds_bank.py`). Reading only `pre.txt` + `sub.txt` takes under a minute for one quarter.

## Automation recommendation: yearly taxonomy diff job (plus a quarterly usage refresh)
Design in 10 lines:
1. Trigger: a monthly GitHub Actions cron (light) checks `https://xbrl.fasb.org/us-gaap/{Y+1}/` and `resources/annualrelease/{Y+1}/` for HTTP 200; it runs only when a new year appears (usually December), and `proposed_updates/` is listed as an early warning.
2. Fetch (not from SEC, so no SEC rate limit; still polite): `us-gaap-{Y}.zip`, `All_Traits_Dictionary.csv`, `GAAP_Release_Notes_Appendixes.xlsx`.
3. Parse into rows of element, period, balance, type, abstract, standard label, definition, calc parents, traits, deprecated flag and replacement.
4. Diff against the previous year: new, deprecated (with replacement and relationship), deleted, definition changed, label changed, period/balance changed, calculation parent changed.
5. Join the diff to `analytics.sec_tag_library` (tags with active_company_count > 0) and to `concept_mapping` (mapped tags): impact = mapped tags first, then high-reach unmapped tags.
6. Join to `data-team/tags/cards/` by tag name: every changed tag that has a card gets a `new` line in `feedback-inbox.md`.
7. Output: a markdown report under `data-team/tags/` plus a CSV artifact. No database writes and no mapping changes: deprecated -> replacement pairs are PROPOSALS for the Tag Mapper (old filings keep the old tag; data-team/23 rule 8).
8. Quarterly companion: when a new FSDS quarter appears, rebuild the label profile for every carded tag (distinct CIKs, top labels, SIC family) and flag any label class that is new for that tag (e.g. a bank printing "income before income taxes" for OperatingIncomeLoss).
9. Guardrails: one process; the SEC_USER_AGENT header for any sec.gov fetch; at most 2 requests per second; caps on file size and wall-clock time; a checksum of the downloaded zip is stored in the report.
10. Owner: the Data Engineer builds it (pipeline or scripts lane, committed migration only if a table is ever needed). The Tag Expert processes its inbox lines, and the calibration table in CHANGELOG tracks how many flagged changes really affected a card.
