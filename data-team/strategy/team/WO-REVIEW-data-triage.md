### 1.2 The shared base query (every cell-level KPI is computed from this, once per scoreboard)
```sql
-- Q0: cell extract. Run per chunk of 100 company ids; one connection; statement_timeout 60s.
-- has_value_any_period exists only after 0096; test information_schema first, as build_coverage does.
select cov.company_id, cov.data_point_name, r.data_point_type,
       cov.has_value, cov.gap_reason, cov.checked_at
       /* , cov.has_value_any_period   -- after 0096; NULL (not false) on concept rows */
from analytics.company_data_point_coverage cov
join analytics.data_point_registry r on r.data_point_name = cov.data_point_name
where cov.company_id = any(%(ids)s);
```
Then in the script, outside SQL: left-join to the D0 grid (986 x 163); a grid cell with no row becomes `absent_from_table`. Companion pass Q0b adds `latest_period_end` and `latest_period_label` per cell (needed for K7 and for the movement decomposition in section 4):
```sql
-- Q0b-concept: latest stored period of each concept cell (25 ids per chunk)
select cf.company_id, cc.name as data_point_name,
       max(p.end_date) as latest_period_end,
       (array_agg(p.fiscal_period order by p.end_date desc, p.start_date desc))[1] as latest_label
from analytics.canonical_fact cf
join analytics.canonical_concept cc on cc.id = cf.canonical_concept_id
join core.period p on p.id = cf.period_id
where cf.company_id = any(%(ids)s)
group by cf.company_id, cc.name;
-- Q0b-metric: the period of the row that defines has_value (same ordering as build_coverage)
select mv.company_id, md.metric_name as data_point_name,
       (array_agg(mv.period_end   order by mv.period_end desc, mv.period_start desc, mv.period_label))[1] as latest_period_end,
       (array_agg(mv.period_label order by mv.period_end desc, mv.period_start desc, mv.period_label))[1] as latest_label,
       (array_agg(mv.value is not null order by mv.period_end desc, mv.period_start desc, mv.period_label))[1] as latest_has_value
from analytics.metric_value mv
join analytics.metric_definition md on md.id = mv.metric_definition_id
where mv.company_id = any(%(ids)s) and md.status = 'active'
group by mv.company_id, md.metric_name;
```
The extract file `data-team/strategy/scoreboard/cells/YYYY-MM-DD.cells.csv.gz` has columns `company_id,data_point_name,data_point_type,has_value,has_value_any_period,gap_reason,latest_period_end,latest_label,absent_from_table`, about 160,718 rows (about 1.5 MB compressed), plus its sha256 in the scoreboard header. ### 1.5 Independence from owners
- **Triage computes every count that is a function of stored tables.** No owner supplies an aggregate. Owners supply only artifacts that cannot be derived: the regression list rows (A20, with expected values from filings), Verifier sample outcomes, Sector Analyst audit outcomes, effort logs, and the analytics source. Those are inputs, labelled `REPORTED` or `INPUT`, and Triage recomputes their arithmetic.
- **Triage draws the samples** (K5b, K6, K11, K13, AT-7.6): `order by md5(id::text || seed)` limited to n, seed recorded in the header and in `cell_evidence.jsonl`, frame size recorded. The role that fixes or proposes a family never chooses the cells that are used to judge it, which removes selection bias that Verifier-chosen samples can carry. Recall frames (cells in a rule's scope with no finding) use a `scope.sql` supplied by the rule's author and checked by Triage against the rule's flagged set (flagged is a subset of scope).
- **Verifier reproduction:** each week the Verifier replays five figures chosen by the Chief from the query files alone (doc 49 one-time condition 5); a figure not reproduced is marked UNVERIFIED until fixed.
- **Triage does not decide classes of correctness.** I do not call a value right or wrong; I report the Verifier's FILING-CHECKED verdicts, the invariant findings, and the arithmetic.
- **Where independence is weaker:** (a) K9 numerator is self-reported; (b) the proxy reason-to-class map is my judgement, so the Chief reviews it once and it is frozen by version; (c) the staleness parity test depends on the Period Engineer's module being correct, which I do not audit.

### 1.6 The defect register view
Three layers, built in this order:
1. **Now (proxy, no migration):** `defects/YYYY-MM-DD.defects.csv`, one row per blank cell and per valued-with-reason cell from the extract, with `defect_class`, `owner`, `rf_id`, `proxy_state`, `proxy_note`, `first_seen_scoreboard`, `last_seen_scoreboard`, `source = proxy`. Class and owner come from `maps/reason_class_map_v1.csv` using only the frozen enums (classes: vocabulary, composition, period, ingestion, resolver, identity, evidence_pending, definition_pending, guard_hidden, finding_open, filer_error, unclassified; owners as the freeze register). Rules: a null reason is `unclassified` / `triage` (shrinks only when K2 does); `line_not_presented_in_filing` is `evidence_pending` / `sector_analyst` (F10); a cascade reason (`incomplete:*`, `missing:*`) inherits the class of its blocking leaf by walking `metric_dependency_graph.csv`, and is `unclassified` when the leaf has no class (the frozen enum has no "cascade" class); `negative_ratio_undefined_cagr` is a candidate `undefined_by_math` but stays `evidence_pending` until the S3 value-proof rule exists. **Unmapped reasons are listed in the header and must be 0 before the register is published.**
2. **At Gate C (`cell_state` v0, Data Engineer, WO-1.3):** the register is `select ... from cell_state where state = 'defect'` (the Data Engineer's view; Triage's script reads it and does not copy its logic). Age comes from my own weekly files, because `cell_state` rebuilds do not keep first-seen dates.
3. **Calibration (two weeks overlap):** the proxy and the real register both run; the difference per class is published as `M.proxy_bias` so nobody has to trust the proxy afterwards.
Closure rule: a defect leaves the register only when the next extract shows the cell in a non-defect state with an evidence reference (AT-7.7, AT-7.15), never because the reason text changed.
