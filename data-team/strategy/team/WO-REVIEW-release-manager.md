### 3.3 My worktree method (used for every release, written so it can be audited)
1. `git fetch origin`; `git worktree add <scratchpad>/wt_<id> origin/main` (detached). In it: `git rev-list --left-right --count origin/main...HEAD` must be `0 0` (Gate A item A3).
2. Per release unit, per file: take the owner's reported file list. For a tracked file, `git -C /Users/vikash/scrooner diff HEAD -- <path> > <scratchpad>/<id>.patch` (never `git stash`, never `git add` in the shared tree); for an untracked file, copy it after `diff` against `/dev/null` and check it is not on origin yet.
3. In the worktree: `git apply --3way <patch>`. A conflict or a hunk outside the owner's declared list = stop and ask the owner; do not resolve by taking the working copy.
4. Run the claimed tests in the worktree (`uv run pytest tests/unit -q`, counts reported), `bash -n`, `check_migrations.py`; `uvx ruff format` only on files in my commit; the CI mypy command exactly as in `ci.yml`.
5. `git add <named paths>`, `git commit` with the section-4 message fields and the Co-Authored-By line, `git push origin HEAD:main` (hook runs), retry up to 3 on non-fast-forward after `git fetch` and `git rebase origin/main`.
6. Verify `git log origin/main -1`; for a workflow change, parse the YAML; remove the worktree; report hash, files, counts, held files.
7. Held branches: `git push origin <commit>:refs/heads/held/<name>` from the worktree (the pre-push hook only gates `refs/heads/main`, so I run ruff/mypy by hand before pushing a held branch, because it will be merged later).

### 3.4 Proposal to eliminate the hazard (one design, two parts; nothing run today)
**Part A (recommended, no reset): one clean worktree per agent, the shared tree becomes read-only history.**
- Each agent works only in its own worktree cut from origin/main on its own branch: `git worktree add ~/scrooner-wt/<role> -b work/<role>/<topic> origin/main`, created by the Release Manager (or Dhairya) at dispatch. `.githooks` is present there, so the hook runs; `uv` and `node_modules` are per worktree (cheap).
- The agent's report names a **branch and commit** (pushed to `refs/heads/work/<role>/<topic>`), not "files changed". Then step 2 of my method is `git cherry-pick`/`git merge --ff-only`, not patch extraction; the "other sessions' uncommitted work" problem disappears because there is none in my view.
- Rules: no agent edits `/Users/vikash/scrooner` directly after the salvage; at most one worktree per active agent; worktrees older than 7 days with no commits are listed for removal. There are already 5 agent worktrees under `.claude/worktrees/` and 4 scratch worktrees (MEASURED `git worktree list`): they are the same pattern working informally; Part A makes it the rule.
- Cost: disk (8 GB Mac, per-worktree venv); mitigate with a shared uv cache and no `node_modules` for pipeline-only roles.
**Part B (one-time salvage, then optional reset of the shared tree). Reset only when no agent is mid-edit; I do NOT run any of this.**
1. Preconditions (all, script-checked): `ListAgents` shows every session idle or acknowledged; Dhairya confirms in writing; the founder's explicit go for the reset (a `reset --hard` is a destructive action I do not initiate).
2. Preserve first: `git branch backup/shared-main-746b80f 746b80f` (keeps the 2 commits not on origin, `9b3e624` and `746b80f`); `git diff HEAD > salvage/tracked.patch`; `git ls-files --others --exclude-standard -z | tar --null -T - -czf salvage/untracked.tgz`; a manifest `salvage/MANIFEST.sha256` of every modified and untracked path; for each unit, a branch `held/...`/`salvage/<owner>` built per 3.3 and pushed to origin. Verify by restoring the tar into a scratch directory and comparing the manifest.
3. Verify nothing was lost: every path in `git status --short` appears in a pushed branch or in the manifest with an owner who confirmed; `git cherry origin/main backup/shared-main-746b80f` shows only commits already accounted for.
4. The reset itself, by the owner of the shared tree after 1-3 (not by me): `git fetch && git switch -C main origin/main` is safer than `reset --hard` because it fails if it would overwrite files that differ; only `git reset --hard origin/main` after the salvage is verified. Never `git clean -x` (it would remove ignored local state such as `.env` files). Ignored files (`node_modules`, local env) survive.
5. After: set `core.hooksPath` check (`ls .githooks`), and add a one-line CLAUDE.md/doc 53 rule: "the shared tree is not an edit location".
Which part do I recommend: **Part A from today** (zero risk), **Part B only if the founder wants the shared tree clean**; if A is adopted, B is optional because nobody works in the shared tree.
