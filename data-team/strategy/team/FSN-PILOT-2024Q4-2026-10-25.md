## Caveat found: cal.tsv does not cover every filer
Of the 988 cohort 10-K/10-Q filings in the quarter, 882 have cal rows and **106 have none**: 67 from filer agent 0000950170 (Workiva), 27 from 0001558370 (Toppan Merrill), 12 others. These are the filers whose calculation linkbase is embedded in the schema (`.xsd`), which our own fallback chain already handles. pre rows exist for all 988, so eras and face lines are complete; only the calc structure is missing for ~11% of periodic filings. `sub.instance` names the instance (e.g. `pld-20240930_htm.xml`), from which the `.xsd` URL follows, so those cals cost ONE request each, no index call.

## What each table could solve beyond cal (Dhairya item 4)
- **num**: every value the filer tagged, including custom tags and dimensioned facts, face and notes: replaces the instance reader for custom liability lines (151 BS companies, 3,958 debt cells), gives dimensioned mezzanine per class of stock (TRGP), and the debt note carrying totals (`LongTermDebt`, `DebtLongtermAndShorttermCombinedAmount`) where companyfacts lacks them. Also the 10-Q-filed-but-zero-facts source gap (companyfacts lacking an accession) for cohort filings.
- **pre**: the face AND note presentation with line order and statement assignment: our eras today use only the face; notes give the debt note table rows and which R page a line is on.
- **txt**: note text blocks: evidence for reasons ("no borrowings", "not applicable"), the zero-debt E2 rule, segment descriptions, fiscal calendar statements (52/53 weeks).
- **dim**: dimension members (segments, class of stock, legal entity): segment revenue, per-class share counts, the multi-registrant (Entergy) context problem.
- **ren**: R-page rendering (which report, which column): lets a Verifier manifest cite the R page automatically.
- **tag**: element definitions incl. custom ones (balance, period type, abstract): the structural guard for custom elements, which the FASB CSV cannot give.
