## How the classification is computed (doc 49 sections 2.1 and 7.6, Dhairya's principle)
Source graph: `data-team/strategy/data/metric_dependency_graph.csv`, code-derived by S1. It has 164 nodes: 76 metrics, 49 leaf concepts, 24 resolved concepts, 6 price metrics, 5 derived concepts and 4 external sources.

For each rule:
1. List the stored nodes the rule acts on. Upstream rules on `core.fact`, identity or authority act on every leaf concept; derivation rules act on every duration leaf.
2. Compute direct and transitive stored consumers of those nodes, excluding the rule's own nodes.
3. Classify:
   - **serve_time** if the rule only hides or relabels and its nodes have 0 stored consumers, or it acts only on a display panel;
   - **recompute_leaf** if it changes the stored value or state but nothing else consumes it, so there is no cascade;
   - **recompute_cascade** otherwise. Dependents are recomputed in topological order in the same release train.

**Limits of the graph:**
- It counts stored metric-to-metric edges only. Serving layers (screener snapshot, company page, backend) read everything and are rebuilt after every train, so they are not counted as consumers.
- It reflects code as of 2026-10-21. Triage keeps it current (WO-7).
- A rule whose nodes later gain a consumer is re-classified when its next version is registered.

## Rule ID scheme, versions and owners
- **Rule IDs and versions.** `family.rule@N` with the `RF-nn` alias (freeze register 3.1). Thresholds are params of the version: changing one is a new version, with a new dry-run and a new Verifier sample.
- **Version class.** Every rule here is at version 1. Each has a version class, PATCH, MINOR or MAJOR (DEFINITION-VERSIONING-SPEC section 4).
- **No accountant at Tier 0.** No Tier 0 rule is MAJOR. Rules that wait for the accountant emit `defect(definition_pending, accountant)`.
- **Who does what:**
  - Owner (definition) proposes.
  - Implementer builds.
  - The Verifier lane must differ from both (Verifier independence).

## One inconsistency in the freeze register (for the Data Chief)
Section 1 says: "A value hidden by a Tier 0 guard is `defect(guard_hidden, <family owner>)`". But the section 3.2 table lists guard families emitting `defect(composition)`, `defect(period)` or `defect(resolver)` (RF-11, RF-13, RF-14, RF-15 and others). A cell can carry only one class.

Proposal:
- class = `guard_hidden` (so K1b counts it);
- owner = the family owner;
- the table's class kept as a separate `root_cause_class` attribute, for Triage's defect register.

I used `guard_hidden` in the state column above, pending the Chief's ruling.
