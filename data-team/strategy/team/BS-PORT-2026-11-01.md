## 1. In one paragraph

The five balance-sheet scripts (`bs_totals_detect`, `bs_assemble`, `era_detect`, `assemble_fsn`, `replay_debt_fsn`) now read one FSN-store company directory (`--company`) as well as the old cohort files. No rule was changed. I ran the old code and the ported code on the same real data: 29 companies, all 59 FSN sets from 2014q1 to 2026m09, sharded by `fsn_store.shard` itself. Cohort mode gives byte-identical output to the old code. Company mode gives the same output as cohort mode. Against the Verifier-passed outputs, 442 of 460 debt cells and 249 of 338 balance-sheet records match exactly. Every other difference has a named cause (section 4). None of them comes from the port. Two of them are real problems in the current lane code that you should know about before the cohort run (section 5).

## 4. Differences that are not defects

4.1 **Input window.** The FSN store starts at 2014q1; the v3 FSDS cohort started at 2015q1. So 10 v3 eras simply start earlier in the store (same era, earlier `filing_from`), and 5 eras end or split one quarter differently (BX, OXY, TRGP). Debt: 32 extra publishable cells, all 2014 instants (the newer replay's 2014 window).

4.2 **OXY equity_parent_tag.** v3 has None, the port has `StockholdersEquity` (3 records). `bs_replay.py` reads `equity_parent_tag or "StockholdersEquity"`, so the same line is read either way.

4.3 **One-offs.** ET 0001276187-18-000025: the FSN face has `NotesPayableRelatedPartiesNoncurrent`, which the v3 FSDS rows did not. DVN 0000950170-24-092424: FSN cal has no balance-sheet group for this filing, so the record borrows the company's other cal (`cal_source borrowed`). Both are face-sum records, so the identity tie still decides publication. Worth one Verifier look each.

## 5. Findings you should act on (none fixed here: each changes values, so each needs the Verifier)

5.1 **Debt: "securities loaned" holds 18 good cells (MSFT 12, GOOG 6).** `era_detect.LABEL_RX` matches "loan" inside "Short-term investments, securities **loan**ed". That is an asset line: MSFT `SecuritiesLoaned`, GOOG custom `SecuritiesOwnedAndLoaned`. The line becomes an uncovered debt candidate, so the record is `coverage_clean=false` and every cell in it is held as `not_computable_uncovered_candidates`. The pilot records behind report_v4 published these cells, and the Verifier passed them (e.g. MSFT 2015-03-31 31,868M). This is in the current `assemble_fsn` cohort path (gate A shows the old code does the same), so the cohort debt build in the handoff would hold them too. It fails safe (blanks, not wrong values). Suggested fix: an asset-side exclusion for `SecuritiesLoaned` / `...AndLoaned` in the coverage check. That needs a Verifier draw.

5.2 **Balance sheet: the UPS equity-block guard drops long-term debt at utilities (70 records: NI 31, AWK 22, FE 17).** The guard came from the Verifier release-1 draw (UPS deferred compensation inside equity). It was added to `bs_totals_detect.py` after v3 was verified. It re-classes any liability line printed after equity starts as equity, and resets only at "Total capitalization". Capitalization-format utilities print equity, then long-term debt, then "Total capitalization". So `LongTermDebtAndCapitalLeaseObligations` (FE, NI) and `LongTermDebtNoncurrent` plus redeemable preferred (AWK) leave the total-liabilities members. These are face-sum records with an identity tie, so the cells should be withheld (gap), not published wrong. But they are blanks the v3 records filled. This is in `main` today, not caused by the port. Suggested fix: in a capitalization layout, do not apply the guard to debt-reading lines before the capitalization total. Then rerun the UPS anchor and these three companies.

5.3 **FSN cal: the largest group with a total-liabilities-and-equity parent is not always the balance sheet.** OXY 0000797468-16-000023 has a larger group (grp2, with cash-flow arcs in it) beside its real face group (grp6). With grp2, `bs_assemble` kept 8 members instead of the filer's 3 roots. I added the opt-in `face_tags` tie-break: the candidate group whose arcs sit on the filing's own BS face wins. It is used by `bs_assemble --company` only. `assemble_fsn` (debt) still uses the old rule, as Verifier-checked (9/9 vs `_cal.xml`). Before the debt cohort run, decide whether debt should use `face_tags` too. It would change some debt records, so it needs a Verifier draw.

## 6. Seeds (`data-team/47-fsn-store/concept_rules/bs.jsonl`)

Exported by `export_concept_rule_seeds_lanes.py` from the lane code, not retyped. A test re-runs the exporter and compares it with the committed file. New since the IS port: 4 `calc_position` rows for `total_debt_resolved`, slots `finance_lease` and `combined`, each `child_of` current and total liabilities. The slot names come from `build_debt_slots.classify()`. Your rules, as given in the brief:

- **Debt includes note finance leases.** A finance-lease face line is a debt member (slot `finance_lease`). A finance lease that sits only in the notes is added by the replay from the same accession (option b). That is a note fact, not a statement line, so it stays in the ported detector and is listed in `lanes_not_extracted.md`. The AMZN test pins it: 2023-12-31 = 78,917M including 12,109M of note finance leases, equal to report_v4.
- **A combined debt + finance-lease line maps to total debt** (slot `combined`; e.g. `LongTermDebtAndCapitalLeaseObligations`, `DebtAndCapitalLeaseObligations`). It is not seeded as a FORMATS-v1 `combined` row, because that would blank it. The old "needs a Standardization call" note is replaced by your ruling.
- **Operating leases stay combined.** No debt slot is ever `operating_lease`, and a test fails if one appears. Lines that mix operating leases with debt exist only as custom elements: the 2025 us-gaap list has 0 standard elements that mix them. The detector keeps those rules: `excluded_mixed_lease` (calc descendants, Verifier V5) and the AMZN operating + finance decomposition. Both are listed in `lanes_not_extracted.md`.

Total: bs.jsonl 16 rows (was 12); 147 lane rules listed as not expressible (lanes_not_extracted.md).

## 7. Tests (CI runs `pytest pipeline/tests`)

`test_bs_fsn_port.py`, 5 tests. They run the scripts the way the gate does (`python -I <script> --company <dir>`), and expected values are read from the committed Verifier files. Mutation-checked: each of these makes a test fail:

- removing `face_tags`
- disabling the note finance-lease addition
- making the instants reader face-only
- removing the `finance_lease` slot from the exporter
- adding an `operating_lease` debt slot
