## 1. Is each WO-3 item doable? Inputs missing? Eligibility per family

### 1.1 Three facts that change the ticket before any family is judged
1. **Counts in S1/doc 46 are cascade cells, not leaf cells.** Example: capex 1,567 "cells" = every blank metric cell that has capex as a cause (fcf, fcf margin, fcf yield, capex % revenue...). The leaf itself is blank for 81 of 986 companies (`capex_resolved`, DATA-INFERRED, cohort_cells.csv). Acceptance must state direct leaf cells and dependent cells separately (AT-3.1e).
2. **A mapping row fills the base concept, but the screen shows the `_resolved` twin.** 29 concepts have a `_resolved` layer (capex, D&A, interest expense, dividends, buybacks, shares, total debt...). That layer is built by conflict fill and by code in `mapper/concept_fallback.py` (D&A is the LARGER of two tags, `resolve_depreciation_and_amortization_max`; capex_resolved adds a software addend; total debt is composed in code). So "add a tag" is (a) a `concept_mapping` row AND (b) for D&A, capex and total debt a code change in a file that is today part of the uncommitted held diff. Each release is also a recompute (resolve-facts, resolve-conflict-fills, fallbacks, metrics) for the touched companies: a heavy-lane job scoped by `ciks`.
3. **The current schema cannot hold an era-scoped or company-scoped mapping with a version.** `analytics.concept_mapping` has priority and confidence only (migration 0004); `company_tag_preference` is per (company, concept) with no period bounds (0051/0072). `first_match` resolves period by period, so a lower-priority row behaves as an implicit era rule (it fires only where the higher tag has no fact for that period) but it fires for EVERY company: the "fallback across tags" that the release tier makes proposal-only (PLAN.md). Live precedents exist (MEASURED, concept_mapping read 2026-10-22): the `cash_flow_investing/financing` continuing-ops fallbacks (0095; they agree with the plain tag in only 80-88% of pairs) and provisional priority-2 rows: capex `PaymentsToAcquireProductiveAssets`, share_buybacks `StockRepurchasedDuringPeriodValue`, dividends_paid `PaymentsOfDividendsCommonStock`, accounts_receivable `AccountsReceivableNet`. Section 4 states what must exist so mappings pass the one-time test.

### 1.2 The narrow class, made script-evaluable (what I propose the founder adopts under item 11)
Founder item 11: a company-scoped tag switch where the filer's own face row carries the same value in the overlap year, no coexisting component tag, coexistence checked population-wide. I can evaluate that in code from `core.fact` alone as a **time bridge**:
- For company C and canonical concept K, tags T_old and T_new, both us-gaap, same unit and period type.
- B1 (bridge): at least one period P (same start/end) with an authoritative fact under T_old (earlier periodic filing) and one under T_new (later periodic filing), values equal within decimals-aware rounding (a rounded copy never replaces a larger-decimals value; TTWO 3,372,772K vs 3,372.8M counts as equal).
- B2 (no coexistence conflict): in no (period, filing) does C file both tags with unequal values, and no third tag of the same family (component or total) coexists in the periods where T_new is used.
- B3 (scope): T_new applies only to C, only after the first bridge period and before T_new's last use (explicit `valid_from`/`valid_to` period ends; open bound allowed and recorded).
- B4 (form and entity): periodic forms only (10-K, 10-Q, amendments, 10-KT), primary-filer rows only (rule P1), USD; SIC 6000-6399 excluded unless the family says otherwise.
- A pair that fails B1 is NOT in the class even if it looks like a rename; it becomes a proposal. A switch that also changes perimeter (adds software, adds notes) fails B1 by value, which is what makes the test useful.
- Limit: B1 needs an overlap year. A company that has only ever used T_new (JNJ/PFE/CL with `PaymentsOfOrdinaryDividends`; most sole-instrument debt filers; MLPs with `PartnersCapital`) has no bridge. For those the second test type is a **face bridge**: the tag sits on the face statement of the right statement role and its value equals the fact (FSDS `pre.txt`/`num.txt`). That needs the structure pilot (WO-1.10) and is NOT script-evaluable today. I recommend the founder adopt the time bridge now and add the face bridge later as a versioned event.
