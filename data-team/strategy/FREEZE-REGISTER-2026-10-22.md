## 2. Cell key and grain (frozen; history must never force a re-key)
- **Cell key** = (`company_id`, `data_point_name`, `period_grain`, `period_start`, `period_end`, `basis`).
  - `period_grain` in {`FY`, `Q`, `TTM`, `I` (instant), `TP` (transition stub, 10-KT)}. Fiscal labels (`fiscal_year`, `fiscal_period`) are attributes, never part of the key (W5/T9 relabels must not move a cell).

- **Latest-period cell** (what v0 materializes): one row per (company, data point) whose period is the **expected** period = the period of the company's latest periodic filing (10-K, 10-Q, 10-KT and amendments) mapped to the data point's grain. Never "the latest period that has a value" (that is the T5 stale-as-current bug). A stale value in the expected cell is `defect(period)` or the RF-23 state.
- **History window**: FY and Q cells for period_end >= 2015-01-01 (doc 38), same key. v0 derives history states on read; a full-history table only after the size check against the 14 GB headroom (doc 49).
- Row identity of a stored state = cell key + `cell_state_run_id`; each row also carries `template_version`, `definition_version`, `rule_id@version`. Serving reads the active run pointer; rollback = repoint.

## 3. Rule-ID scheme and the family register
### 3.1 Scheme
- ID = `family.rule@N` (N = integer version). The registry key `RF-nn` is a stable alias for cross-references. A threshold or condition change is a new version that re-runs the dry-run and the Verifier sample (doc 48 section 3.0).
- One rule registry keyed by (`group`, `data_point_name`, `rule_id`) holds every Tier 0 guard, reason and state rule; each entry carries emitted state, defect class, owner, train, consumer count (computed from `data/metric_dependency_graph.csv`: more than 0 consumers = recompute train, 0 = serve-time allowed, doc 49 2.1), and a rollback flag name (= the rule ID). Tier 1 migrates registry rows into `metric_template`, not code.
- Every guard and reason emits a state code from section 1 plus its rule ID, never free text.
- Certify rules are detectors, namespaced `cert.I<k>.<rule>@N` (e.g. `cert.I6.non_periodic_form@1`). A guard that acts on a certify finding cites both IDs.
