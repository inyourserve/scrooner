- **Filed values: FILING-CHECKED.** **Stored Scrooner values: DATA-INFERRED.** They are quoted from the shard files because no database tool was available in this session. So I verify what the filing says, and that the shard's stored value matches a specific wrong source fact. I did not re-read our tables.
- Shared-parser caveat: one regex reader (`<tr>` rows plus the `defref_` tag in each row) read every R-page. Footnote `<sup>` cells were dropped (ledger row 2026-10-18). Values were spot-read against row labels, but nothing independent such as edgartools cross-checked the parser.

## Root-cause families (for the Chief)
1. **total_debt base concept** (1a-1e): two separate faults in one sum rule. (i) Current-only or zero-only sums when LongTermDebtNoncurrent or the LongTermDebtAndCapitalLeaseObligations* family is not in the sum (LLY, RTX, ABBV). (ii) Double count when LongTermDebt (which includes current maturities) is added to DebtCurrent (CSCO, TMO). total_debt_resolved is right at LLY and RTX but wrong at CSCO. Next step: the face-statement debt rule needs a full-population dry-run before any fix.
2. **Bank/broker revenue** (2a-2b): the priority-4 gross interest tag wins over the face total.
3. **Proxy values winning** (3a-3b): the DEF 14A pay-versus-performance facts are tagged us-gaap:NetIncomeLoss, and at MRK the filer put continuing ops on that tag.
4. **Partial-cost gross margin** (4a-4b).
5. **No staleness guard on "latest"** (5a-5b). GE also shows that a segment-summary fact can sit on a consolidated tag.
6. **Precision-consistent duplicates treated as conflicts** (6).
