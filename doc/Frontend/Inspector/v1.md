# Review: Apple (AAPL) Company Research Page — Design & Credibility Audit

> **Frontend architecture note (2026-09-06):** This document contains historical implementation evidence from the retired frontend. Current guidance is one Next.js App Router application on `scrooner.com`: `/` owns company search, the public screener, and broad stock-screener SEO intent; `/stocks/*`, `/screens/*`, `/pricing`, `/learn`, `/glossary`, and `/blog` are public and indexable; every logged-in surface lives under `/app/*`.

**Reviewed as:** a financial advisor/expert (trust and correctness lens) and a top-tier
product designer (Airbnb-caliber simplicity lens), against the rendered HTML/CSS of
`apps/site/src/pages/stock/[ticker].astro` (Apple example) and cross-checked against
`claude/scrooner-financials-display-spec-final.md`.

**Overall verdict:** The underlying data model is sound (correct TTM/balance-sheet
handling, real SEC provenance, sensible naming — all per the financials spec). The page
fails on two axes instead: internal numeric consistency (numbers that quietly disagree
with each other), and visual/brand coherence (the page runs two different color systems
and two different design metaphors at once). Screener.in's appeal is that every number
feels agreed-upon and the whole page reads as one quiet, correct ledger. This page
currently reads as several well-built widgets stapled together.

---

## 1. Trust/credibility bugs (financial-advisor lens — fix first, these are cheap and high-damage)

1. **ROE shown as two different numbers with no reconciliation.** Hero/decision-row: ROE
   119.9% (TTM · 2026-06-27). Rule-based "Positive signals" bullet: "high return on
   equity of 157.5% over the last 3 years." Same page, same company, no label
   distinguishing snapshot vs. 3-year average — reads as an error to anyone who notices.
2. **ROIC shown as two different numbers, same problem.** 85.2% TTM in the decision row
   vs. 78.0% "over the last 3 years" in the signals bullet list.
3. **Raw internal error string exposed to users.** The Interest Coverage cell's
   `title`/`aria-label` reads literally: *"Not computed for the latest period:
   incomplete:denominator."* This is an internal exception message, not reviewed copy,
   and a screen-reader user hears it verbatim.
4. **Template bug leaking a field label into body copy.** About section: *"Company
   Background The Company designs, manufactures and markets..."* — the field label
   "Company Background" got concatenated directly into the paragraph with no
   punctuation separating it.
5. **Peer comparison is financially incoherent.** Peers are matched by strict legacy SIC
   code 3571 ("Electronic Computers") and return Super Micro Computer, Dell, Omnicell,
   and One Stop Systems as Apple's "peers" — a $4.5T consumer/services company next to a
   ~$2B industrial-hardware company. This is the single most damaging item on the page
   for anyone who knows the company even slightly; it undermines trust in every other
   number.
6. **Unlabeled units in the segment revenue table.** Rows like "6581.00" carry no
   per-row unit (millions/thousands); only a general footnote says units vary by filing.
   Unlabeled numbers are a real landmine on a finance site.
7. **Inconsistent empty-state and currency tokens.** Blocked values render as "—", "Not
   available", or the raw error string above depending on the cell; some dollar figures
   carry "$" (Book Value, Market Cap), others don't (Public Float). Small individually,
   adds up to "this wasn't proofed."

## 2. Design/visual problems (why it doesn't feel Airbnb/screener.in-caliber)

1. **Two brands in one page.** Header logo, "Sign in to screen" button, and footer all
   run on the site's teal (`--ds-color-action`, `#0e7c66`, from `public-theme.css`). But
   `company-research.css` redefines `--brand-700`/`--link-700` twice in the same file —
   first to `#6765f4` (indigo), then, later in the same file, to `#5369b7` (slate-blue) —
   and the second silently wins the cascade. Every content link, the chart line, and all
   hover states render in slate-blue while the header/footer stay teal. This is cascade
   drift (accumulated copy-paste, not a design decision), and it's directly visible on
   every page load.
2. **The page argues with its own design brief.** A comment in the page's own CSS says
   ledger tables should look "like a printed statement, not a dashboard widget" — and
   the statement tables mostly deliver on that. But the surrounding chrome (soft drop
   shadows on every card, rounded pill badges everywhere, colored signal chips, a bar
   chart for ownership mix) is dashboard-widget styling. Half the page wants to be a
   printed statement, half wants to be a SaaS analytics dashboard; nothing has been cut
   to commit to one metaphor.
3. **Delayed price styled as a warning.** "Delayed · 19:59 ET" renders in
   `--warning-700` (amber) directly under the headline price. Delayed data is normal for
   a free tool; amber reads as "something's wrong" before the reader has processed
   anything else. Screener.in-style treatment: quiet gray, same weight as any other
   metadata label.
4. **Three overlapping insight systems instead of one.** The "Analysis" decision-rows,
   "What changed recently" change-list, and "Rule-based observations" bullet disclosure
   all narrate the same handful of facts (e.g., operating margin's +0.5pp move appears
   in two of the three) in three different visual shapes. Screener.in's core trick is a
   single, simple Pros/Cons list — instantly scannable, screenshot-able. Splitting the
   same narrative across three components with different shapes means none of them reads
   as definitive.
5. **Metric fatigue from repetition.** Operating Margin, ROE, ROIC, and Net Margin each
   appear in 3–4 different modules (hero key metrics, Financial Overview grid, decision
   rows, full Ratios catalogue) at slightly different periods/labels. Nothing is
   individually wrong, but the reader can never be sure which box is "the" answer.
6. **Critical disambiguation buried in a closed `<details>`.** The note explaining that
   institutional (64.1%) + "other" (35.9%) is a two-category split that must NOT be
   summed with insider ownership (0.1%, shown separately) lives inside a collapsed
   disclosure most users will never open — so most users will misread the ownership bar.

## 3. The one-sentence summary

Screener.in feels like a single, quiet, correct ledger. This page feels like four
well-built widgets from four different sprints stapled together — teal brand vs. blue
content, printed-statement tables vs. dashboard chrome, and three overlapping opinions
about whether Apple is a good stock, two of which use ROE/ROIC numbers that visibly
don't match each other.

## 4. Fix priority

1. Fix the color-token collision — run the whole page on the site's teal brand token,
   remove the duplicate `--brand-700`/`--link-700` redefinition in
   `company-research.css`.
2. Pick one insight format (Pros/Cons, screener.in-style) and delete the other two. This
   is the natural home for the `plain_english_note` / Signal-chip work already planned
   in `scrooner-financials-display-spec-final.md` Section 4 — consolidate into it rather
   than adding a fourth format.
3. Reconcile or clearly re-label every duplicated metric (TTM vs. 3-year average,
   especially ROE/ROIC) so no two numbers on the page can look like they disagree.
4. Strip dashboard chrome (drop-shadows, decorative pills where not load-bearing) and
   commit fully to the "printed statement" aesthetic the page's own CSS comments already
   call for.
5. Fix or prominently caveat the peer-comparison logic — highest-trust-impact item on
   the page for a knowledgeable reader.
6. Sweep for leaked-string bugs: Interest Coverage tooltip, "Company Background" copy
   bug, unlabeled segment units, inconsistent "—"/"Not available" tokens.
7. Re-skin the delayed-price label to neutral gray.
8. Surface the institutional/insider ownership disambiguation outside the collapsed
   disclosure, at least as a one-line caption on the ownership bar itself.
