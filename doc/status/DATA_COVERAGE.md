**Updated 2026-09-13, direct follow-up to a real user bug report ("financials is core of Scrooner and we have lots of empty rows") — found and fixed the single most consequential bug in this whole file: the company page's statement tables had been silently serving stale, unresolved data for 5 of 8 balance-sheet rows for days, because a code fix was never re-applied to the database.** Migration `0059` (2026-09-09, documented in `pipeline/CLAUDE.md`'s same-day entry) repointed `classify.py`'s `STATEMENT_LINES` at 19 new `*_resolved` concepts — but repointing the Python *source* is not the same as the live table actually reflecting it. `analytics.statement_line` (what `apps/app`'s company page actually queries) is a small, denormalized table built by running `scrooner-map seed-statements` once; that command was never rerun after the migration 0059 code change landed, so the live table kept serving the OLD, unresolved concept for Current Assets, PP&E, Total Assets, Total Liabilities, and Stockholders' Equity — only "Total Debt" had ever been correctly repointed. **Updated 2026-09-12 — new standing methodology: coverage must be measured against the population a data point actually applies to, never against the whole active-company count by default.** Prompted directly by a real user report that turned out to be a measurement problem, not a data problem: `revenue` coverage looked like 87.4% against all 5,216 active companies, which reads as "13% of companies are missing something they should have" — wrong, because 400 of those 5,216 are not operating businesses at all (SPACs pre-merger, royalty/pass-through trusts, commodity/crypto ETF trusts like SPDR Gold Trust) and structurally never file a Revenue line. **Cross-verified the real-company universe size three independent ways before trusting a corrected number**: Alpaca's trading API asset list (`paper-api.alpaca.markets/v2/assets`, not the market-data API — filtered to major exchanges + tradable + fund/trust/warrant/note name patterns excluded) lands at 5,392, within 3.4% of ours; yfinance's own `y_industry = 'Shell Companies'` tag independently confirms 327 SPACs; and the hardest remaining cases (foreign filers, utility co-registrant subsidiaries) were checked by fetching each company's own live SEC companyfacts payload directly. **Against the corrected 4,816-company real-operating-company denominator, revenue coverage is 98.7%, not 87.4%** — 4,523 real values + 78 real top-line data under the sector-correct concept (bank/BDC/REIT) + 143 genuinely-and-correctly pre-revenue (biotech, mining exploration) + 10 real SEC-side data-availability limits (FPI/co-registrant), leaving only 62 companies (1.3%) genuinely unexplained. Two candidate tag additions that looked safe on a small sample (`ElectricUtilityRevenue`, `RegulatedAndUnregulatedOperatingRevenue`) were checked at full population scale and **rejected** — 62% disagreement, both mix a company-wide total with a business-segment-only value under the same bare tag for other companies (Alliant Energy Corp: same tag, $35M vs. a real $1.03B total in the same period) — left honestly unexplained rather than force-fixed. Mechanism: `mapper/coverage_matrix.py`'s `classify_concept_gaps()`, wired into every `build-coverage-matrix` rebuild — see `pipeline/CLAUDE.md`'s same-day entry for the full rule list.
