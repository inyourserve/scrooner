# 2026-09-10 — Screener catalog widened to all 82 metrics (including price-dependent ones); one live data bug found and fixed

Prompted by "make it world's best screener" — audited what the Screener actually exposes versus what's already computed and sitting unused.

## The gap

`screener/resolve.py`'s `load_screenable_metric_catalog()` and `apps/backend/routers/screen.py`'s `_load_metric_catalog()` both filtered `requires_price = false`, excluding all 11 price-dependent metrics (Market Cap, P/E, P/S, P/B, Dividend Yield, FCF Yield, EV/EBITDA, EV/Sales, PEG Ratio, Buyback Yield, Total Shareholder Yield) from the Screener entirely. This was a real, deliberate stopgap from doc 14 (2026-08-17), written when those metrics only had mock price data. `pipeline/CLAUDE.md` already anticipated this exact widening ("no screener/ code change needed when that changes") — and it's now true: checked live before removing the filter, `market_cap` has real values for 4,410/5,216 active companies (84.5%), `price_to_book` 82.6%, `trailing_pe` 62.7%. Real, substantial coverage, not a token handful.

Removed the filter in both places (`resolve.py`, `screen.py`). No other code changed — the snapshot table, boolean-tree compiler, and citation logic already treat every `metric_definition_id` uniformly.

Separately found: 34 of the resulting 82 metrics (including all 11 price ones, plus several already-screenable EDGAR metrics like `payout_ratio`, `pretax_margin`, `net_cash`, `working_capital`) had no entry in `apps/backend/metric_catalog.py`'s `METRIC_PRESENTATION` dict — they fell back to an auto-generated label (`presentation_for()`'s own graceful default) and an "Other" category. Added proper display names, definitions, and categories for all 34, including two new categories (`Valuation`, `Shareholder returns`) that didn't exist before because nothing needed them.

The AI Query Engine's rule-based parser (`ai_query/aliases.py`) already had aliases for every one of the 11 price metrics ("market cap", "p/e", "peg ratio", "ev/ebitda", etc.) — built ahead of time, waiting for the Screener to accept them. Confirmed live: `market cap above 500 billion`, `PE below 20`, `EV/EBITDA` all now resolve and run correctly, no `ai_query` code change needed for the metric names themselves.

## A real gap found testing it: no investor types the zero-padded number

`market cap above 500000000000` worked; `market cap over 500 billion` did not — the deterministic parser's value grammar (`^([\d.]+)(%)?$`) had no concept of magnitude suffixes, because every metric screenable before today was a percentage or a small ratio, where nobody needs "15 billion percent." The instant Market Cap became screenable, this became a real, expected-on-the-first-try phrasing, not an edge case.

Fixed in `ai_query/rules.py`: a `_MAGNITUDE_SUFFIXES` table (k/thousand, m/mn/million, b/bn/billion, t/tn/trillion) folded into both the single-value (`VALUE_RE`) and `between`-clause (`BETWEEN_RE`) grammars, plus comma-stripping and an optional leading `$`. Verified live: `500 billion`, `500billion`, `500B`, `500bn`, `$500 billion`, `1 trillion`, `1T`, `500,000,000,000` all parse to the identical `Decimal`; existing percentage-metric queries (`roe above 30%`) are unaffected (the suffix group is optional, checked with a regression test). 15 new tests, `tests/unit/test_ai_query_magnitude_suffixes.py`.

## A live, trust-destroying data bug found in the process

The very first thing tried against the newly-widened catalog — "companies with market cap over $500B" — surfaced **Akari Therapeutics Plc at a computed $1.74 trillion market cap**, ahead of Meta, Tesla, and Micron, in the middle of an otherwise perfectly correct top-10 (NVIDIA, Apple, Alphabet, Microsoft, Amazon, Broadcom, ... all real, all correctly ranked). Exactly the kind of result that would destroy a first-time user's trust in one glance.

Root-caused before touching anything: both inputs are real, as-filed, `is_authoritative=true` XBRL facts, not a Scrooner parsing bug — `EntityCommonStockSharesOutstanding` from Akari's own 2026-08-13 10-Q genuinely says 155,758,529,533 (155.7 billion), and the $11.15 price is a real, current Alpaca-sourced quote for ticker AKTX. The company is a UK-incorporated, Nasdaq-listed micro-cap biotech using an ADS (American Depositary Share) structure — the share count and the traded price almost certainly live on two different bases (ordinary shares vs. ADSs) that this pipeline has no mechanism to reconcile, a genuinely hard, foreign-issuer-specific edge case, not a quick fix.

Sized before fixing, not assumed: queried every company with a shares-outstanding figure over 20 billion (a deliberately loose net) across all history, found a large historical cluster (Oracle 2012, PG&E 2015-2017, ON Semiconductor, Truist, CNA Financial, Seagate, Yum Brands, Chubb — all old, pre-2022 dates) that looks like a genuine historical XBRL scale-parsing issue, but confirmed **none of it reaches today's live market_cap** — those companies' current market caps are all correct, because `price_metrics.py` correctly picks the most recent shares-outstanding fact, not a stale corrupted one. Also confirmed several current penny stocks with real, very large share counts (Healthier Choices Management, World Health Energy Holdings, TAP Real Estate, GBT Technologies) either have no computed market_cap at all (honest null, no price data) or a plausible one (UPEXI $73.8M, BILI Social $849.8M) — Akari was the **only** live anomaly above $500B, confirming this is an isolated, narrow case, not a systemic bug.

Fixed with a one-off, evidence-documented correction: nulled `market_cap`, `ev_ebitda`, `price_to_book`, and `total_shareholder_yield` for this one company (`company_id=2781`) directly in `analytics.metric_value`, with `is_null_reason` explaining exactly why, then rebuilt the screening snapshot (`scrooner-screen build-snapshot`, dataset_version 1→2). Verified live: the $500B+ market-cap screen is now a clean, fully correct top-10. **Not a permanent fix** — this correction will be silently overwritten the next time `calculate-price-metrics`/`calculate-expanded-metrics` reruns for this company, since neither of those modules has an override mechanism analogous to `company_tag_preference`/`canonical_fact_sanity_override`. Flagged here, not solved: a real ADS-ratio-aware fix, or at minimum a generalized "market cap implausible relative to sector/history" sanity check reusing the existing `sanity/` layer, is the right next step if this recurs.

## Net result

Screenable metric catalog: 71 → 82. Full pipeline suite 511 → 526, backend suite 27 (unchanged count, one hardcoded-count regression test updated), all passing. Confirmed live end-to-end: a real market-cap screen, a real P/E screen, and a real magnitude-suffix natural-language query all return correct, verified-against-reality results through the actual HTTP API.
