# Create-screen typeahead: "type 're', see metrics; type 'ab', see 'above'" (2026-10-02)

Prompted directly, with a concrete example: typing "re" into the create-screen box should show matching metrics (Return on Equity, Return on Invested Capital, ...) the way company search already shows matching companies as you type; continuing with "ab" should show "above". Built end to end, mirroring the exact architecture `lib/company/search.ts` already proved for company search: fetch the vocabulary once, rank entirely client-side, zero network/DB round trip per keystroke.

## Why this couldn't just copy company search verbatim

Company search ranks a company's own ticker/name against the whole typed string. A screen query is a full sentence with multiple roles in it — a metric name, then an operator, then a value, then maybe another clause — so "what should be suggested" depends on *where in the sentence* the cursor currently is, not just "what's been typed so far." Two matching checks run together: does the **current clause since the last "and"/"or"** match a phrase as a whole-prefix (handles "re" → "return on equity" when nothing else has been typed yet), and does the **last word alone** match a phrase as a prefix (handles "roe ab" → "above", without "roe " getting swallowed). Both are plain `startsWith` checks against the real alias vocabulary — no fuzzy matching, no guessing; the earlier same-day typo auto-suggestion is a separate, deliberately different feature (near-miss correction via `difflib`, triggered after a full word is typed and doesn't match anything).

## What got built

- `GET /v1/nl-vocabulary` (`apps/backend/routers/screen.py`) — exposes `ai_query/aliases.py`'s own `METRIC_ALIASES`/`OPERATOR_ALIASES`/`SECTOR_ALIASES`/`SECTOR_BUCKET_ALIASES`/`AMBIGUOUS_METRIC_PHRASES` as JSON. No DB query, no duplication — the exact dicts the real parser resolves against, so a suggestion can never name a phrase the parser wouldn't also recognize. No auth (matches `/v1/metrics`/`/v1/ask`'s own "free to try" design).
- `GET /api/nl-vocabulary` (Next.js proxy, `apps/app/app/api/nl-vocabulary/route.ts`) — same auth-gate + caching shape as the existing `/api/metrics` route.
- `lib/screener/suggest.ts` — `loadNlVocabulary()` (module-singleton fetch + same-day localStorage cache, identical pattern to `loadCompanyDirectory()`) and `getSuggestions(vocabulary, text, cursor)` (the dual clause/last-word matching above), plus `applySuggestion()` (replaces only the matched extent, inserts the phrase plus a trailing space).
- Wired into `NaturalQueryPanel.tsx`: a floating dropdown under the textarea, arrow-key navigation, Enter/Tab to accept, Escape to dismiss, click to insert (via `onMouseDown` preventDefault so the textarea never blurs on click).

## Two real bugs found building the test coverage, not assumed away

1. **If the vocabulary fetch resolved *after* the user had already started typing, suggestions would never appear until the next keystroke** — the mount effect only set state, nothing re-triggered `getSuggestions()` against whatever was already in the box. Fixed by recomputing against the textarea's live value/cursor the moment the vocabulary promise resolves, not just on the next `onChange`/`onSelect`.
2. **`role="combobox"` on the textarea silently reclassified its accessible role away from "textbox"**, breaking 9 existing, unrelated tests that query it by `getByRole("textbox", ...)` — caught immediately by running the full suite, not assumed safe. Removed; kept `aria-controls`/`aria-activedescendant` (which don't require the combobox role) and dropped `aria-expanded`/`aria-autocomplete` (which do, per `jsx-a11y`'s own lint rule).

## Verification

- `lib/screener/suggest.test.ts` (10 tests): the dual-matching logic in isolation — whole-clause-prefix vs. last-word-prefix, clause-boundary reset after a literal "and", case-insensitivity, the 2-character minimum, capping, and that replacement never swallows an earlier word.
- `NaturalQueryPanel.test.tsx` (7 new tests, React Testing Library, real DOM interaction — not just unit logic): typing "re" shows both "Return on equity" and "Return on invested capital" as clickable options and clicking one inserts the full phrase; typing "roe ab" suggests "above" and clicking it produces "roe above " (the earlier word survives); Enter accepts the active suggestion; Escape closes without touching the text; gibberish never shows a dropdown at all. Found and fixed, while writing these: a stale same-day `localStorage` cache left over from earlier tests in the same file silently defeated a later test's own fetch stub — added `__resetNlVocabularyCacheForTests()` (test-only) that clears both the module-level promise and the cache key, used in every `afterEach`.
