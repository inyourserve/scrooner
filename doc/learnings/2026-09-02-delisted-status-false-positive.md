# 2026-09-02 — 222 active companies falsely marked `delisted`

## What happened

While verifying `total_debt_resolved` coverage during the XBRL tag-coverage-library rollout (doc 40), found that `total_debt_resolved` (a new fallback-merged concept) was missing 170 companies that should have had data. Tracing this down surfaced a much bigger, unrelated bug: **222 companies in `core.company` — including AMD, Intel, HP Inc, Caterpillar, US Bancorp, Applied Materials, Fifth Third Bancorp, Dollar General — had `status = 'delisted'`**, set by a `company_master update-status` run on 2026-08-23.

This mattered well beyond the tag-coverage task: any full-population batch job whose CIK list is generated by filtering `core.company` on `status='active'` (which today's rollout does) silently excludes every `delisted`-flagged company — even though the underlying `core`/`raw` data for these companies is fine and current, since the Collector/Normalizer don't filter by status at all.

## Root cause

`company_master/status.py`'s delisting inference (doc 23 Stage C / doc 24 Phase 1) already has a real safeguard, added after an earlier false-positive (JPM's Chase Capital trust filings, documented in this same file's own docstring): a Form 15/15F is only trusted as a real delisting if its own cover page's "Title of each class" field mentions "common stock" — not just any deregistration.

That safeguard is real but not sufficient. Checked live: **192 of the 222 companies had a genuinely "common stock"-titled Form 15 on record, but then kept filing real 10-Ks/10-Qs for years or decades afterward** — AMD's Form 15 dates to 1996-02-09, and it filed a 10-Q on 2026-08-05. This is almost certainly a historical Section 12(g)→12(b) exchange up-listing (deregistering from an OTC/NASDAQ-national-market 12(g) registration when the company moved to full NYSE 12(b) listing, common for companies that grew large decades ago) or a specific security class sharing the parent CIK — not the company itself going private. The existing cover-page check correctly confirmed the text said "common stock," but had no check for whether the company was still obviously alive afterward.

## Fix

`status.py` gained `_load_latest_form15_dates()` and `_deregistration_overridden_by_later_filing()`: a confirmed common-stock Form 15 is now discarded as a delisting signal if a real qualifying 10-K/10-Q was filed after it. `update_status()` applies this before trusting `is_deregistered`. Covered by 7 new unit tests (`tests/unit/test_status.py`); full suite 319/319 passing after the change.

Rerunning `update-status` for the 222 affected CIKs: **192 correctly reactivated to `active`** (`delisting_signal_overridden_by_later_filing: 192` in the stats), **30 stayed `delisted`** — no qualifying filing exists after their Form 15 for any of these 30, consistent with a genuine deregistration (not individually re-verified one by one, but the absence-of-later-filing signal is the same honest, conservative test doc 23's original design already relies on elsewhere).

## Follow-up executed same day

Launched a supplemental 6-stage Mapper pass (`resolve-facts` → `resolve-concept-fallbacks` → `calculate` → `calculate-expanded-metrics` → `calculate-piotroski` → `calculate-quality-flags`) scoped to exactly the 192 reactivated CIKs, run alongside the already-in-progress full-population tag-coverage rollout (4 workers for this supplemental pass, 8 for the main one — kept under the pool's connection ceiling, verified live). This both closes the current metric-coverage gap for these companies and brings them current on every fix from today's tag-coverage work (`total_debt_resolved`, the derived `gross_margin`, the 3 new fallback tags).

## Lesson

**A defensive check that closes one known false-positive mode is not proof the signal is now fully trustworthy — a signal confirmed correct in the way it was designed to be checked can still be systematically wrong in a dimension nobody checked yet.** The cover-page "common stock" text match was real and correctly implemented; it just wasn't sufficient on its own, because the deeper assumption (a Form 15 mentioning common stock always means an ongoing delisting) was never verified against filing recency, the one signal already being computed for every company in the same function. Before trusting a confirmed signal as final, ask what a genuinely wrong instance of it would look like under the data already on hand, not just whether the check as designed passed.

This is also the second time in this project a full-population run surfaced a false positive invisible at golden-10 scale (the first being Form 4/13G issuer-vs-filer mismatches, doc 19) — reinforcing that scale itself is a verification step, not just a throughput milestone.
