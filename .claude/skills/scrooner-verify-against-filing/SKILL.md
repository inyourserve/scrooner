# Verify against the filing

Evidence class is FILING-CHECKED only if you read the filing's own R page (or FSN rows). A verdict never depends on production's value or on the builder's code path. Read `README.md` here for existing readers; reuse them, do not rewrite them. Kit: `pipeline/src/scrooner_pipeline/verification/filing_kit.py`.

## Inputs (all come from the dispatch brief)
Branch and commit under test; report files (manifest of cells: cik, instant, shown/withheld, era); claimed counts (ties, withheld, publishable); seed. Missing one: BLOCKED, ask. Work in a worktree at that commit; never touch the shared tree.

## Derive from the face, independently
- Liabilities: printed "Total liabilities"; else printed total liabilities and equity - total equity (incl. NCI) - printed mezzanine (redeemable / temporary equity / OP units). Never sum children; never trust the builder's members.
- Routes: (1) R page via `FilingSummary.xml` -> `fetch_statements` (1 + 3 requests per filing); (2) FSN rows (financial statement and notes data sets) when the R page is absent or the era predates R pages.
- Parse columns by date, not position (old R pages have a leading blank column). Check scale (thousands/millions) before comparing; tolerance is half the printed rounding unit.
- A cell is read from the accession it claims, not a later restatement.
- `FaceLiabilities.combined=True` (several registrant blocks): first block used; confirm it is the registrant you verify. `unavailable`, or an equity footed from components, is a hand-read cell, not evidence.

## Sample design (`seeded_sample(manifest, seed)`)
Per company: first, last, every era boundary, every reading B instant (taxonomy-total-covered roots), every withheld cell, plus seeded random picks. Record the seed so a re-run picks the same cells. Failing-era companies get more picks. Re-read by hand any cell your automation disagrees on before calling it wrong (a parser slip is not a builder error; say how many you re-read).

## Gate wording
**GATE: zero wrong shown values.** Report "N of N shown cells right" and the count wrong. Never "99%". One wrong shown value fails the batch; name the cell, accession, R page, shown vs face.
- Withheld cells whose value the face gives: list as AVOIDABLE HOLDS (not failures), with the face derivation.
- False holds (holding was correct, e.g. face contradicts the identity): list in a separate section. Do not mix the two lists.

## Verdict file
`data-team/strategy/team/VERIFY-<NAME>-<YYYY-MM-DD>.md`, generated by `verdict_skeleton(...)`. Fixed sections: Result, Method, Sample, Cell table, Withheld cells (avoidable holds), False holds, Findings for the builder, Requests and disk, Untested scope. First line states branch+commit; second states seed, files, claimed counts. Findings name an action ("use printed subtotals as members"), and say what to re-verify after the fix.

## Appends before you finish
- `data-team/22-FILING-LESSONS-LEDGER.md`: one row per new filing lesson: `| date | topic | lesson | accession | FILING-CHECKED |`.
- `python3 mind/mind.py add --title ... --kind ... --evidence <accession+R page> --tags ...` for durable findings (search first with `mind.py search`).
- `data-team/tags/feedback-inbox.md`: one line per tag learned (meaning, misuse, company usage), format in that file. Do this even if the task did not ask.
- Commit the verdict to a branch and push the branch; never main. Message includes the SEC request count.

## SEC and disk rules
- sec.gov only; User-Agent from `SEC_USER_AGENT` in `pipeline/.env`, never a hard-coded or invented one.
- At most 4 requests/second, one process, no parallel fetchers. Use `SecClient` (it enforces rate, domain, disk floor).
- Delete every download when done (`/private/tmp` only; floor 4 GB free; `df -h /private/tmp`). Report the total request count.
- No DB writes, no migrations. Reads: one connection, explicit `statement_timeout`, and only if the brief needs it.
